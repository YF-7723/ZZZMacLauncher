# 性能报告：M1 Pro 16GB 上运行《绝区零》Windows 版

> 实测日期：2026-10-22 ~ 2026-10-23
> 机器：MacBook Pro 14"（MacBook Pro 14-inch）· Apple M1 Pro（8 核：6P+2E / 14 核 GPU）·
> 16GB 统一内存 · macOS 27.0.1 · 插电、未降频
> 游戏：绝区零 国服 3.3.0 Windows 客户端（本体零修改）

---

## 一、问题链条与状态

| 环节 | 现象 | 状态 |
|---|---|---|
| 反作弊驱动 | `WDFLDR.SYS not found`、`initDriver Failed: Error [4,1114,0]`、启动闪退 | ✅ 已修复（WDF 兼容模块） |
| 客户端版本 | 3.2 过期无法登录 | ✅ 已更新到 3.3.0 |
| 游戏内资源下载 | 游戏内下载器单连接速度低（~10MB/s） | ✅ 已下载完成（外部多连接可 59MiB/s） |
| **性能** | 主城 30~40 帧、战斗 <30 帧 | ⚠️ 已定位瓶颈：**CPU 转译 + 16GB 内存**，GPU 有余量 |
| **垂直同步** | 游戏内开启，帧数被锁 30/60 | ⚠️ 需在游戏内关闭（最有效的手感改善） |

## 二、运行链路与瓶颈定位

```
绝区零（x86_64 PE） → Wine 11.0（含 DXMT） → Rosetta 2（x86_64→ARM64） → Metal → Apple M1 Pro
```

游戏内高画质实测（标题界面 60 秒 / 游戏内观察）：

| 指标 | 数值 | 说明 |
|---|---|---|
| GPU 时间 | ~10 ms | GPU 未饱和（14 核 GPU 仍有约 50% 余量） |
| GPU 利用率 | 40~60% | 不是 GPU 瓶颈 |
| CPU 占用 | 375%+（≈3.9 核） | 转译 + 游戏逻辑，主要瓶颈 |
| 内存 | ~10 GB（进程内 7.7GB + 系统） | 16GB 机器压力大，会触发内存压缩/换页 |
| Metal 显存 | ~3 GB | |
| FPS | 主城 30~40 / 战斗 <30 | 受垂直同步与 CPU 双重限制 |

**结论：瓶颈在 CPU 转译（Rosetta + Wine 指令翻译）与 16GB 内存上限，不在 GPU。**
因此优化方向是：降低 CPU 负载（设置项、运行时）、降低内存占用、改善帧生成节奏（垂直同步/帧率上限）。

## 三、运行时方案对比

| 方案 | 能否游玩 | 说明 |
|---|---|---|
| **Wine 11.0 + DXMT（D3D11）** | ✅ 稳定 | 本项目采用；反作弊正常；实测可长时间游玩 |
| Wine 11.20 + D3DMetal（DX12）+ MetalFX | ❌ 反作弊崩溃 | 进世界时 MHYPBase 崩溃；详见 `docs/EXPERIMENTS.md` |
| Wine 11.20 + D3DMetal（DX11） | 未验证 | 无 FSR/帧生成，收益有限 |
| 其他 Wine/DXMT 组合 | 未完成 | 网络与时间限制，未做完整 A/B |

## 四、标题界面基准数据（`metalperftrace`，60 秒）

| 方案 | FPS | 帧时间 avg | 帧时间 std | GPU 时间 | CPU 提交 | 内存 | Metal 显存 |
|---|---|---|---|---|---|---|---|
| DXMT（Wine 11.0） | 28.0~28.2 | 35.5~37.9 ms | 20.8~38.8 ms | 7.8~15.9 ms | 5.88 ms | 2.8 GB | 0.55 GB |
| D3DMetal DX12（实验） | 29.2 | 33.8 ms | 6.5 ms（缓存后） | 15.1 ms | 33.7 ms | 5.2 GB | 1.0 GB |

> 重点看帧时间稳定性、CPU 提交时间与内存占用。

## 五、游戏内设置建议（实测推荐）

| 设置 | 推荐值 | 理由 |
|---|---|---|
| **垂直同步** | **关闭** | 开启时帧数锁 30/60，是手感最大的杀手 |
| 帧率上限 | 60 / 无限 | 配合关闭垂直同步 |
| 画质预设 | 高（卡则中） | 预设主要影响 GPU，但部分项吃 CPU |
| 渲染精度 | 1.0（追帧数可 0.85） | 0.85 约 +10~15% 帧数 |
| 阴影精度 | 中 | 阴影是 CPU 大户 |
| 全局光照 | 中 | Apple GPU 无硬件光追，高 GI 收益低 |
| 角色质量 | 中 | 省内存 |
| 特效质量 | 中 | 省 CPU/内存 |
| 光线追踪 | 关 | 不可用 |
| 体积雾 / 环境光遮蔽 | 关/低 | |
| 动态模糊 / 景深 | 关 | 提升清晰度 |

## 六、系统层优化（已应用/建议）

| 项目 | 状态/建议 |
|---|---|
| Spotlight 索引 | 已将 80GB 游戏目录加入排除（`.metadata_never_index`） |
| 电源 | 插电 100%，无低电量模式，未降频 ✅ |
| Swap | 机器连续运行 18 天、swap 已用 1.88GB/3GB → **建议重启后长时间游玩** |
| DeepSeek Harness 本体 | Renderer 约 77% CPU（≈1.2 核）→ 游玩时可关闭，用手机查看 |
| Steam++ | 约 4.5% CPU → 不玩其他游戏时退出 |
| ToDesk | 常驻后台 → 不需要时退出 |
| WindowServer | 后台 UI 渲染占用 → 关闭浏览器/聊天软件后明显下降 |

> 游戏运行时若同时开着上述程序，相当于少 1.5~2 个 CPU 核，
> 在 6P+2E 的 M1 Pro 上可能造成 20~30% 的帧数差异。

## 七、结论与后续

**当前最优可用配置**：
- Wine 11.0 + DXMT（稳定）
- 游戏内：关垂直同步、帧率 60、画质高/中、阴影/角色/特效中、渲染精度 1.0（或 0.85）
- 系统：重启后游玩、关闭后台大程序

**无法实现的优化**：
- FSR 帧生成 / MetalFX 插帧：反作弊不兼容（`docs/EXPERIMENTS.md`）
- 60 帧满帧：CPU 转译硬瓶颈（8 核中 4 核被吃满），除非官方提供 ARM 原生客户端

**可复现测量**：见 `docs/BENCHMARK.md`，脚本在 `scripts/bench/`。
